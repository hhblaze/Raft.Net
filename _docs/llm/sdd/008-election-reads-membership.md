# Elections, read fences, transfer, and configuration

Status: implemented and validated by the final 221-test suite, 42,000 seeded runs and real 3/5-process kill/rolling membership workflows. See the current validation record.

Authority: [Ongaro dissertation](https://github.com/ongardie/dissertation), §9.6 pre-vote, §3.10 transfer, §6.4 reads, chapter 4 membership; [the 2015 correction](https://groups.google.com/g/raft-dev/c/t4xj6dJTP6E/m/d2D9LrWRza8J) requires a committed current-term entry before creating a configuration.

- Pre-vote carries prospective term and round; it changes no durable receiver state, does not reset the election timer, respects recent leader contact, and counts distinct active voters. Learners/removed nodes never campaign or grant votes. Default heartbeat/election ratio is at least 10.
- ReadIndex captures a commit fence after a current-term entry commits, sends a unique context to an active voter majority, and waits for local application. New requests admitted after a heartbeat was sent use another round. Old/missing contexts, learners, duplicate replies, and an isolated leader cannot satisfy the fence. No log write is needed. Existing ReadBarrierAsync remains an additive compatibility API.
- Transfer stops proposals, catches up a voter, sends TimeoutNow, and observes that target's higher-term leadership. It aborts within an election timeout. Invalid/rejected/busy control requests are client errors, while persistence/application failures remain fail-stop.
- The latest configuration in the durable log is active immediately, including an uncommitted entry. Refresh through the configuration index after suffix replacement to recover/roll back exactly. One changed server/role, one uncommitted configuration, a current-term committed entry, minimum voter count, and a bounded-lag learner promotion are enforced. Leader removal counts only the new voters, announces the final commit, then retires.
- KnownPeers is a separately provisioned network identity list, never an implicit voter list. A receiver with an old log can receive a legitimate new leader's request. The receiver must itself be a voter to grant a vote; candidates count responses only from their current voters. Group/peer authentication belongs in the transport. Provision future IDs/endpoints on all nodes before adding a learner. Do not bootstrap a replacement with a conflicting voting set.
- Historical member IDs are persisted as bounded auxiliary metadata, allowing retirement notification after restart. Retired peers receive the final configuration/commit and then stop replication; they do not count toward quorum. Bootstrap and active configuration are independent of this auxiliary list.
- Protocol v2 adds correlation IDs, entry kinds, pre-vote, read contexts, TimeoutNow, and snapshot chunks. Explicit v1 fixtures still preserve old bytes; v1 and v2 transports reject mixed activation. Snapshot transport messages exist, but installation/compaction through the node is still pending.

Evidence: `.artifacts/autonomous/test-results/membership-full.trx` (151/151), focused read/transfer (9), focused membership (7). Real TCP/disk membership cases cover both 3 and 5 voters plus a spare. This is not a completion claim for the full enhancement scope or a benchmark result.
