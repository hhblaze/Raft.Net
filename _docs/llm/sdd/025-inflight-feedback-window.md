# Include in-flight proposals in feedback collection

Status: implemented R16,329tests/integration passed; superseded default-window tuning by R17/spec026. The two-layout uncommitted-feedback regression fails on R15 and passes here. Target3node median beats both refs,5node Pipeline loses15.5%base, all rounds retained. The larger wire budget reduced follower appends from273 to216–217 per4096 commands, but leader grouping became smaller and no throughput gain was demonstrated.

The collector currently grants its bulk window only when published commit exceeds local apply. Commands already durably assigned or sent for a quorum can also produce another application/client feedback wave. Excluding them permits a small queued remainder to flush after2ms while most of the closed-loop workload is still uncommitted.

Use admitted work outside the payload queue (admitted count greater than queued count) as the runtime-only feedback indication. The collector reads atomic admission/short-gate queue metadata, never reducer state. Continue shortening to the small window when no other admitted work remains. Default automatic bulk delay becomes min(16×small delay,one heartbeat,1second), normally25ms. Explicit bulk values are unchanged. Count/byte/role limits and single-voter1ms cap remain. Deadlines originate at oldest admission, never extend on new arrivals, and the owner never waits for the timer.

Before changing production, reproduce on v2/v3: hold data RPCs after one proposal is durably assigned but before quorum; queue another byte-limited command; verify it retains the bulk window despite no committed backlog. A higher-term vote must be processed before that second command is indexed. Both uncommitted callers must receive NotLeader and release admission. Then focused/full safety/integration, real write counts and fresh rotated capacity trials. No speed claim from the scheduling test; explicit throughput/collection-latency trade-off remains part of configuration/reporting.
