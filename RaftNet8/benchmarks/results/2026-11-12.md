## Allocation observation

The first warmed wire run exposed identifier-validation and entry-enumerator allocations. Replacing string LINQ validation with a direct character loop and encoding entries by index reduced managed allocation:

| Operation | Before | After |
| --- | ---: | ---: |
| Encode heartbeat | 96 B | 32 B |
| Encode AppendEntries, 32 × 256-byte commands | 128 B | 32 B |
| Decode that AppendEntries | 11,168 B | 11,168 B |

The remaining encoding allocation is the pooled frame owner; command payloads are copied on decoding so they remain valid after the rented receive buffer is returned. The two short runs are not sufficient to claim an across-the-board speedup: AppendEntries encoding had a slightly higher mean after the allocation change, with overlapping confidence intervals. See the [before](wire-before-2026-11-12.md) and [after](wire-after-2026-11-12.md) reports.

## Storage and end-to-end baseline

The [append report](append-2026-11-12.md) compares 1/32/128-command durable transactions, with 256-byte commands, in disk and memory modes. Its mean is per **batch transaction**, not per command. The [TCP report](tcp-2026-11-12.md) measures 256 concurrent proposals per iteration, normalized per command and acknowledged after quorum persistence plus leader application. Its application is a volatile counter, so it excludes durable business-side effects. These measurements are amortized throughput costs, not per-request latency percentiles.

Disk timings have wide confidence intervals, and the short single-invocation jobs report minimum-iteration-time warnings. Do not use these results as capacity promises or cross-host latency estimates. The demo's load timer is likewise an end-to-end functional observation, not a controlled comparison. Longer isolated runs on the deployment hardware, with realistic application transactions and network delay, remain necessary for capacity planning.

The reproducible benchmark commands and exact workload boundaries are in the [benchmark README](../README.md). CI configuration covers Windows and Linux; only Windows execution was available and observed in this workspace.
